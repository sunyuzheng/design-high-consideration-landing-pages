# Sources and Provenance

This skill was abstracted from repeated, real-world revisions of two high-consideration product pages. The examples are case-study material, not templates or current product contracts.

## Public Case-Study Surfaces

- Stay Superlinear: https://stay.superlinear.academy
- AI Builders 2027: https://ai-builders.com

The accompanying field notes preserve the reasoning and failure modes learned during those revisions. They intentionally omit machine-local paths, private repositories, internal offer ledgers, member data, credentials, and unpublished source material.

## How to Use the Examples

- Treat product names, prices, counts, testimonials, entitlements, and page structures as dated examples.
- When working on either source product, re-open its current public page and locate the current project owners before making factual claims or production changes.
- When working on another product, reuse only the reasoning patterns and failure lessons. Do not copy the case-study language, brand proposition, proof, visual system, or page order.
- If a cited detail cannot be verified from the current project or an authorized source, mark the gap instead of treating this skill as evidence.

## Skill Design Provenance

The skill follows a result-oriented design: define the job, acceptance criteria, resources, boundaries, and known real-world failure modes while leaving room for the agent to choose an appropriate method. It uses progressive disclosure so the core workflow stays in `SKILL.md` and longer case-study observations remain in `references/field-notes.md`.
